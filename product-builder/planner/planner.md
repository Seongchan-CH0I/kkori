## 1. 서비스
**꼬리(kkori)** — 매일 기술면접 질문 하나에 답하면, AI가 면접관처럼 피드백하고 꼬리질문을 던진다.
대상: 신입·주니어 백엔드 취준생. 마스코트는 여우, 연속 기록 = 꼬리 길이.

루프: `08:00 알림(cue) → 답변·피드백·꼬리질문(routine) → 연속 기록(reward)`

MVP 범위를 이 세 축에 하나씩만 배치했다. 루프가 돌기 전에 보상을 늘리면 활성화 지표가 오염되어 리텐션 원인을 못 읽는다.

## 2. 범위
- **MVP**: 오늘의 질문 / 답변 피드백(스트리밍) / 꼬리질문 3단 / 질문 알림 / 연속 기록
- **2단계**: 주간 약점 리포트, 스터디 모드
- **안 한다**: 점수화, 모범 답안, 음성, 이력서 기반 질문, 랭킹·리더보드, 결제, 다직군 질문 은행

## 3. 사용자 행동 가정
> 기능 설계의 전제. 백엔드가 부하 시나리오를 만들 때 쓰는 입력값이기도 하다.

- **아침 알림이 유일한 진입 트리거다.** 사용자가 스스로 앱을 여는 걸 기대하지 않는다.
- 하루 **1세션**, 세션 길이 5~10분. 하루 2문제는 제공하지 않는다.
- 세션 안에서 꼬리질문 3단까지 가는 비율은 **40% 가정**.
- **전원이 같은 날 같은 질문 풀을 본다.** 개인화는 2단계.
- 연속 기록은 사용자별 데이터이고, 홈 진입마다 조회된다.
- 실사용자는 대표 + 스터디원 10명. 대규모 수치 가정은 백엔드 담당.

## 4. 기능 요구사항
### 4-1. 오늘의 질문
- 하루 1질문 고정. 같은 날 다시 들어오면 같은 질문
- KST 자정에 새 질문으로 전환
- 지난 30일 안에 받은 질문은 제외
- 건너뛰기 하루 1회, 연속 기록은 끊기지 않는다
- 뽑을 질문이 없으면 빈 상태 화면. 에러 화면을 보여주지 않는다

### 4-2. 답변 피드백
- 제출 후 **3초 이내에 첫 글자**가 보이고 이어서 흐른다. 빈 화면으로 기다리게 하지 않는다
- 화면을 벗어났다 돌아오면 생성된 부분까지 보이고 나머지가 이어진다
- 결과는 `좋은 점 / 빠진 점 / 한 줄 정리` 3블록
- 10자 미만은 AI를 호출하지 않고 즉시 입력 안내
- 하루 재시도 2회까지. 단 **끊긴 피드백을 이어받는 건 재시도로 세지 않는다.** 네트워크가 끊긴 건 사용자 잘못이 아니다
- 끊겨서 재시도해도 **중복 과금이 없다**
- AI가 실패해도 **답변은 저장되고 연속 기록은 인정된다.** 장애로 사용자가 손해 보지 않는다

### 4-3. 꼬리질문
- 모범답안이 아니라 **내가 쓴 답을 근거로** 더 깊은 질문 1개
- 깊이 **3단 고정**. 3번째 답변 뒤에는 "여기까지 따라왔어요" 마무리
- 맥락 = 원 질문 + 내 답변 + 직전 피드백
- "모르겠어요"에는 비난 없이 핵심만 2~3줄. 더 내려가지 않는다
- 언제든 그만하기 가능. 연속 기록은 첫 답변만으로 인정
- 자유 대화(챗봇)로 열지 않는다. 하루 1루프라는 구조가 습관을 만든다

### 4-4. 질문 알림
- 기본 08:00 KST, 질문 카테고리까지 포함한 문구
- 시각 변경은 다음 날부터 적용
- 그날 미답변자에게만 21:00 리마인드. **하루 최대 2건**
- 알림을 끈 사용자는 발송 대상에서 제외
- 탭하면 홈이 아니라 **답변 화면으로 직행**
- 푸시 1채널만. 이메일·카카오톡은 안 한다

### 4-5. 연속 기록
- 오늘 **첫 답변** 제출 시 +1. 꼬리질문 답변은 추가로 세지 않는다
- 중복 제출해도 **하루 1회만** 증가한다
- 하루 빠지면 연속은 1로 리셋. **누적 답변 수와 최장 기록은 보존**
- 7일·30일에 꼬리 모양이 눈에 띄게 달라진다
- 현재 연속 / 최장 / 누적 답변 수가 홈에서 보인다
- 스트릭 프리즈, 배지, 랭킹은 안 한다. 10명 규모에선 비교가 압박이 된다

## 6. 그로스
- 첫 사용자 = 대표 + 스터디원 5~10명. 공개 배포·마케팅 없음, 접근은 허용 목록
- 초대 코드 없음. 가입 장벽을 늘리지 않는다
- 보는 지표 하나: **활성화(가입 후 5분 내 첫 답변) + D7 리텐션**
- **알림 권한은 첫 세션을 끝낸 직후 홈에서 묻는다.** 피드백과 꼬리질문을 한 번 겪은 뒤에 물어야 "왜 필요한지"가 설명 없이 전달된다
- 온보딩 화면(시작 → 핵심 루프 → 첫 질문)은 Should. MVP에는 넣지 않고 알림 권한도 여기 넣지 않는다
- 피드백 수집: 3일차 앱 안 한 줄 질문 / 1주차 "어제 왜 안 열었어요?" 직접 묻기 / 대표 매일 사용 일지
- **판단 기준: 2주 뒤 D7이 10명 중 4명 미만이면 기능 추가를 멈추고 꼬리질문 품질만 고친다.** 루프가 안 돌 때 기능 추가는 전부 낭비다

## 7. 열린 질문 (대표 결정)
1. **배포 형태** — 일반 웹 vs 토스 미니앱. 웹이면 iOS 푸시 제약 때문에 4-4의 "푸시 1채널" 전제가 흔들린다. 기획 범위에 직접 걸리는 유일한 기술 결정.
2. **LLM 제공자** — 스트리밍 필수. 4-2의 "3초 이내 첫 글자"가 지켜지는지가 선택 기준.
3. **질문 은행 출처** — 직접 작성 vs 공개 레포 가공. planner가 안을 가져올지, 대표가 정할지.
